Per-user limits on an MCP server that knows no users

Entra ID app roles, a token Foundry gets on the user's behalf, and an APIM policy that enforces them.

  1. The need. One Foundry agent serves several users from a general news service, GNews, through its MCP server and one API key shared by everyone. User A may read every news category; user B only sports, science and health.
  2. The gap. The MCP server is third-party (GNews). It knows one API key and no users, so it cannot restrict anyone, and you cannot change it.
  3. The fix. Foundry swaps the user's token for one that carries their Entra app roles. APIM validates that token and checks each tool call against the roles before it reaches GNews: an allowed call goes on with the API key, and a refused call never leaves APIM.
